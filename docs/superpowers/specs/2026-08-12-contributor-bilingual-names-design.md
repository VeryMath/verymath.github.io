# VeryMath 首页成员名单与双语姓名设计

日期：2026-08-12
状态：待书面审阅

## 目标

VeryMath 首页使用一个统一的 `Contributors / 贡献者` 成员墙，完整覆盖两类实际参与者：

1. 已有公开贡献或指导关系记录中的成员；
2. 2026-06-30 `AI4Math · VeryMath` 团队介绍中的 14 名成员。

两类来源合并后按真实身份去重，共展示 21 人。指导老师王祥丰固定排在第一位，其余成员按中文姓氏拼音排序，同姓时按名字拼音排序。

贡献者卡片遵循首页统一语言状态：英文页面只显示英文姓名，中文页面只显示中文姓名。GitHub 头像、账号、主页链接、卡片身份和排列位置不随语言切换改变。

## 方案选择

采用统一成员墙、数据层双语字段和静态排序：

- 已有贡献者、指导老师和团队介绍成员合并到同一份 `_data/contributors.json`；
- `name_en`：英文姓名，统一采用“名 + 姓”顺序；
- `name_zh`：中文姓名；
- `initial_en`：英文模式下头像失败或无头像时的缩写；
- `initial_zh`：中文模式下头像失败或无头像时的姓氏文字；
- `github`：已确认的 GitHub 登录名，无法确认时为 `null`；
- `role`：`advisor` 或 `member`，用于验证老师置顶，不在卡片中显示等级标签；
- `evidence`：公开贡献、指导关系或团队介绍来源。

JSON 数组本身保存最终展示顺序，Liquid 直接按数据顺序渲染，不在浏览器中重新排序。页面继续使用既有 `.lang-en`、`.lang-zh` 和 `data-vm-lang` 机制，不新增姓名专用 JavaScript 字典。

未采用以下方案：

1. 分成 `Team` 与 `Contributors` 两区：多人同时属于两类，会重复出现并引入不必要的身份边界；
2. 按有无 GitHub 分区：账号确认状态不应形成成员等级；
3. 在同一卡片中始终显示 `English / 中文`：不符合现有语言切换，也会增加移动端拥挤；
4. 在 JavaScript 中维护账号到姓名的翻译字典：会让身份数据分散在两个文件，并增加无脚本页面的不一致风险。

## GitHub 尚未确认时的处理

只有经用户确认或有可靠公开证据的 GitHub 登录名才写入 `github`。团队介绍本身只证明成员身份，不证明 GitHub 账号归属。

对 `github: null` 的成员：

- 使用当前语言对应的首字母或姓氏占位头像；
- 卡片使用不可点击的静态容器；
- 不显示空账号、问号、`pending` 标签或错误链接；
- 不将团队介绍中的个人照片复制到公开网站；
- 以后确认账号时，只需补充 `github` 与证据，页面即使用 GitHub 头像和主页链接。

不从 Git 提交邮箱、相似用户名或头像相似度推断身份，也不在公开首页显示成员邮箱。

## 页面渲染

每张卡片的姓名节点包含两个语言子节点：

```html
<span class="vm-contributor-name">
  <span class="lang-en">English name</span>
  <span class="lang-zh">中文姓名</span>
</span>
```

备用头像文字采用相同结构。英文模式显示两到三个拉丁字母缩写，中文模式显示一个姓氏汉字。GitHub 头像成功加载后继续覆盖备用文字；头像加载失败时，当前语言对应的备用文字保持可见。

GitHub 账号行始终显示同一 `@github`，链接地址不随语言改变。老师与其他参与者使用相同卡片样式；老师只通过数据顺序置顶，不添加排名、贡献次数或视觉等级标签。

贡献者区域说明同步涵盖团队参与和指导支持：

- English: `We thank everyone who contributes tools, workflows, research infrastructure, teamwork, and guidance to VeryMath.`
- 中文：`感谢所有为 VeryMath 的工具、工作流、科研基础设施、团队协作与指导支持作出贡献的参与者。`

## 数据迁移与来源边界

将现有 `_data/contributors.json` 中的 `name`、`initial` 分别迁移为双语字段，并增加 `role`。`github` 原样保留，记录数量由 16 增加到 21，已确认 GitHub 的记录数量保持 11。

已有公开贡献记录继续保留 GitHub URL 作为 `evidence`。新加入且暂无公开 GitHub 证据的团队成员使用受控来源标识 `team-introduction-2026-06-30`，不把本机绝对路径或团队介绍文件复制进公开仓库。页面不渲染 `evidence`。

页面模板不再读取旧的 `name` 或 `initial` 字段。测试应拒绝混用旧字段，防止未来新增记录只提供一种语言。
