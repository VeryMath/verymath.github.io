# VeryMath 首页贡献者区域设计

日期：2026-08-12
状态：已获用户确认

## 目标

在 VeryMath 网站首页最下方增加 `Contributors / 贡献者` 区域，展示对 VeryMath 公开成果有实际贡献的个人。名单必须覆盖通过导入、课程整合或代提交进入仓库、因而未被 GitHub contributor API 正确识别的贡献者。

## 非目标

- 不把 VeryMath 组织成员资格等同于贡献。
- 不展示提交次数、排行榜或贡献量排序。
- 不在浏览器中聚合全部仓库的 GitHub API。
- 不展示内部名册、年级、专业、私人邮箱或未经公开确认的真实姓名。
- 本次不改动首页其他模块，也不发布网站。

## 方案决定

采用仓库内的静态贡献者登记表 `_data/contributors.json`，由 Jekyll 在构建首页时读取。首页只渲染登记表，不依赖运行时 API，因此不会受到 GitHub 未登录限流、网络失败或提交归属缺失的影响。

每条记录包含：

- `name`：公开展示名，沿用公开归属记录中的写法；
- `github`：经直接提交、PR 或保留的源仓库历史确认的公开 GitHub 登录名，没有则为 `null`；
- `initial`：无头像或头像加载失败时的文字占位；
- `evidence`：一条或多条公开贡献证据，用于维护和测试，不在首页展示。

不根据姓名相似、组织成员列表或邮箱猜测 GitHub 账号。若后续获得明确的账号映射，只更新数据文件，不修改页面结构。

## 纳入与去重规则

个人满足以下任一条件即可纳入：

1. 出现在 VeryMath 公开仓库的 `CONTRIBUTORS.md` 中；
2. 出现在已发布技能包的公开课程归属或 provenance 记录中；
3. 作为非机器人作者出现在 VeryMath 公开仓库提交历史中。

去重顺序如下：

1. 相同 GitHub 登录名视为同一人；
2. 公开归属文件明确给出的姓名与账号映射视为同一人；
3. 其余相似名称不推断合并。

仅有组织成员身份但没有上述贡献证据的账号不纳入；机器人账号和团队名称不纳入。维护者只要具有实际公开贡献，按相同规则展示，不单独置顶。

## 页面布局

贡献者区域放在 `Join the Ecosystem / 加入生态` 之后、站点页脚之前，确保它是首页内容的最后一个模块。

区域包含：

- 双语标题 `Contributors / 贡献者`；
- 一句双语说明，明确感谢对 VeryMath 公开工具、工作流和研究基础设施作出贡献的人；
- 响应式头像卡片网格。

每张卡片展示圆形头像或文字占位、公开展示名，以及存在时的 `@github`。有确认账号的整张卡片链接到 GitHub 个人主页；没有账号的卡片保持为非链接内容。头像使用 GitHub 公共头像地址并延迟加载，头像不可用时保留文字占位和姓名。头像使用空 `alt`，可访问名称由卡片中的可见文字提供。

桌面端采用自动填充网格；窄屏保持至少两列，在极窄屏降为一列。卡片沿用首页现有白底、细边框、圆角和克制阴影，不新增装饰性配色。

名单按公开展示名稳定排序，不按贡献量排序。

## 数据与渲染流程

1. 维护者审核公开归属证据和账号映射证据后更新 `_data/contributors.json`。
2. Jekyll 构建时通过 `site.data.contributors` 生成完整 HTML。
3. 浏览器无需请求贡献者 API；仅按需加载公开头像。
4. 语言切换继续使用现有 `.lang-en` 与 `.lang-zh` 机制。
5. GitHub 头像或个人主页不可用时，页面仍保留姓名和文字头像，不影响其余内容。

## 验证设计

实施时先添加失败测试，再编写页面代码。验证范围包括：

- 数据文件是有效 JSON，字段完整，展示名和 GitHub 登录名均不重复；
- 当前名单恰好包含上述 15 个去重后的公开身份；
- 每条记录至少有一条公开贡献证据；
- 首页在 `Join the Ecosystem` 后包含双语贡献者标题和 Jekyll 数据循环；
- 有账号与无账号两种卡片都具有可用的静态回退；
- 页面不新增贡献者 API 请求、贡献次数或排名文案；
- 桌面和移动视口均无横向溢出，语言切换和键盘焦点可用；
- 原有首页内容、Star 数量回退和现有分支中的课程成果模块保持不变。
